ЧЕК-ЛИСТ ТЕСТИРОВЩИКА 
1. Перед началом тестирования 
Сначала познакомьтесь с проектом и попробуйте понять его как обычный 
пользователь. 
О проекте 
• Я понимаю, для чего нужен этот проект. 
• Я понимаю, кто является его пользователем. 
• Я понимаю, какую проблему пользователя он решает. 
• Я могу назвать основные функции проекта. 
• Я понимаю, какой результат должен получить пользователь. 
Вопросы тестировщика 
Перед началом работы ответьте: 
Для чего нужен проект? 
Кто его пользователь? 
Какие основные задачи пользователь может выполнить? 
 
2. Запуск проекта 
Проверяем, можно ли вообще начать работу. 
• Проект открывается. 
• Проект запускается без очевидных ошибок. 
• Понятно, что нужно сделать после запуска. 
• Понятно, как начать работу. 
• Пользователь понимает, что происходит после запуска. 
• Нет сообщений об ошибках, мешающих началу работы. 
Если обнаружена проблема, зафиксируйте её в таблице тестирования. 
 
3. Главное меню и навигация 
Проверяем, насколько понятно перемещение по проекту. 
• Понятно, какие разделы доступны. 
• Понятно назначение кнопок. 
• Кнопки выполняют заявленные действия. 
• Можно перейти в нужный раздел. 
• Можно вернуться назад. 
• Можно повторить действие. 
• Нет тупиковых экранов/состояний. 
• Пользователь понимает, где он находится. 
• Названия разделов понятны. 
• Навигация логична. 
 
Вопрос тестировщика 
Если я впервые открыл этот проект, смогу ли я самостоятельно понять, куда 
нажимать? 
• Да 
• Частично 
• Нет 
 
4. Проверка основных функций 
Теперь проверяем, действительно ли проект выполняет свои основные 
задачи. 
Для каждой функции задайте три вопроса: 
Что я делаю? 
Что должно произойти? 
Что произошло на самом деле? 
Проверка функций 
• Основная функция проекта работает. 
• Все основные кнопки работают. 
• Все необходимые поля ввода работают. 
• Поиск работает, если он предусмотрен. 
• Результат отображается. 
• Переходы между разделами работают. 
• Можно выбрать нужный вариант. 
• Можно изменить выбор. 
• Можно вернуться назад. 
• Можно повторить операцию. 
• Результат соответствует запросу пользователя. 
Важно: если функция отсутствует, не ставьте автоматически FAIL. 
Запишите это отдельно как возможное предложение по улучшению или 
ограничение проекта. 
 
5. Позитивное тестирование 
«Пользователь делает всё правильно» 
Проверяем обычные сценарии использования. 
Проверьте: 
• Правильный ввод данных. 
• Обычный пользовательский сценарий. 
• Корректный запрос. 
• Выбор существующего варианта. 
• Повторное выполнение успешной операции. 

=== PAGE 2 ===
• Использование основных функций в предусмотренной 
последовательности. 
Пример 
Действие: ввести существующее ключевое слово. 
Ожидаемый результат: система показывает соответствующие результаты. 
Фактический результат: _________________________________ 
Статус: PASS / FAIL / PARTIAL 
 
6. Негативное тестирование 
«А что будет, если пользователь сделает что-то неожиданное?» 
Попробуйте специально использовать нестандартные варианты. 
Ввод 
• Оставить поле пустым. 
• Ввести одно слово. 
• Ввести несколько слов. 
• Ввести очень длинный текст. 
• Ввести неправильный запрос. 
• Ввести запрос, по которому нет результатов. 
• Сделать опечатку. 
• Ввести цифры. 
• Использовать специальные символы, если это допустимо. 
• Ввести несколько пробелов. 
Действия пользователя 
• Быстро повторить одно действие. 
• Нажать кнопку несколько раз. 
• Вернуться назад. 
• Вернуться назад несколько раз. 
• Попробовать изменить предыдущий выбор. 
• Попробовать начать действие заново. 
Главный вопрос 
Как система сообщает пользователю о неправильном или неожиданном 
действии? 
• Сообщение понятное. 
• Пользователю понятно, что делать дальше. 
• Система не «зависает». 
• Система не переходит в непонятное состояние. 
 
7. Проверка интерфейса 
Теперь временно забудьте о функциях и посмотрите на проект глазами 
пользователя. 
7.1. Понятность 
• Понятно, что нужно делать. 
• Понятно, куда нажимать. 
• Названия кнопок понятны. 
• Сообщения понятны. 
• Термины понятны пользователю. 
• Нет непонятных сокращений. 
• Результат действия понятен. 
7.2. Читаемость 
• Текст хорошо читается. 
• Размер текста удобен. 
• Текст не обрезается. 
• Строки/сообщения не выглядят перегруженными. 
• Важная информация хорошо заметна. 
• Нет очевидных ошибок в тексте. 
7.3. Кнопки и элементы управления 
• Кнопки визуально понятны. 
• Понятно, что кнопка является кнопкой. 
• Название кнопки соответствует её действию. 
• Кнопки не перекрывают друг друга. 
• Кнопки не обрезаны. 
• Нет элементов, которые выглядят активными, но не работают. 
7.4. Структура 
• Информация расположена логично. 
• Нет лишней информации. 
• Связанные элементы находятся рядом. 
• Пользователю не приходится выполнять слишком много лишних 
действий. 
• Интерфейс выглядит последовательным. 
 
8. Проверка сообщений системы 
Особое внимание уделите тому, что проект сообщает пользователю. 
• Понятно, что произошло. 
• Понятно, что делать дальше. 
• Сообщения соответствуют ситуации. 
• Нет непонятных технических сообщений. 
• Нет сообщений на другом языке без необходимости. 
• Нет очевидных ошибок и опечаток. 
• Сообщение об ошибке действительно объясняет проблему.

Например

«Error 504».

9. Проверка результатов 
Когда система что-то нашла, сформировала или показала, необходимо 
проверить сам результат. 
• Результат появился. 
• Результат соответствует запросу. 
• Информация понятна. 
• Информация полная. 
• Результат можно использовать для выполнения задачи. 
• Нет очевидно нерелевантных результатов. 
• Результат не противоречит введенным данным. 
 
10. Проверка повторного использования 
Не ограничивайтесь одной попыткой. 
• Можно повторить действие. 
• Результат повторяется предсказуемо. 
• Можно изменить запрос. 
• Можно выполнить другую функцию после первой. 
• После возврата назад проект продолжает работать. 
• После нескольких последовательных действий проект не переходит 
в ошибочное состояние. 
 
11. Итоговая проверка команды 
Перед завершением работы убедитесь, что вы: 
• Проверили запуск проекта. 
• Проверили основные функции. 
• Проверили навигацию. 
• Провели позитивные тесты. 
• Провели негативные тесты. 
• Проверили интерфейс. 
• Проверили сообщения системы. 
• Проверили результаты работы. 
• Записали найденные проблемы. 
• Сделали скриншоты проблем. 
• Указали важность проблем. 
• Нашли минимум 3 положительные стороны. 
• Сформулировали предложения по улучшению. 
• Заполнили таблицу тестирования. 
• Проверили, что все участники команды внесли вклад в работу.
